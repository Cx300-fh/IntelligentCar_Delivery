One complete loop, not a pile of modules.

系统的核心体验是一条连续链路：浏览器创建订单，电脑后端转发给小车，小车取件、行驶、避开高成本道路，最后到站提醒取货。

Order

Create mission

浏览器提交地图、起点、终点和订单编号，电脑端后端把任务转成小车可执行 UDP JSON。

Plan

Weighted Dijkstra

边权由基础距离、动态路况、人工难走配置和封路状态共同决定。

Drive

Navigate by tags

AprilTag 节点作为定位锚点，导航状态机输出跟线、直行、转向、停止动作。

Adapt

Reroute in motion

电脑端可下发拥堵、事故、天气或人工封路权重，小车按最新成本重规划。

Deliver

Prompt and confirm

到起点播报“请放入物品”，到终点播报“请取走物品”，确认后推进订单状态。

The campus is not static.

地图展示的是导航层，而不是调试图。基础道路弱化，当前路线高亮，只有拥堵或封路边才进入视觉焦点。

Talk to the car.

本地 ASRPRO 负责固定播报，电脑端语音网关负责命令理解。外部模型 API 可以替换规则解析器，而小车端协议保持 UDP JSON。

User voice

“确认已放入” / “Stop mission” / “查询当前状态”

ASRPRO

串口识别文本进入小车语音模块，转发给电脑端模型网关。

UDP 8899

电脑端返回 confirm、stop、submit_order、speak 等结构化动作。

Vehicle

调度器推进订单状态，或触发 ASRPRO 本地播报 ID。

Local voice first

起点、终点、任务开始、取消、完成、异常状态都映射到本地播报 ID；外部模型只理解命令，不负责生成音频。

Under the hood.

电脑不是简单前端，而是通信网关：它托管控制台、收发 UDP、转发 WebSocket、写入 SQLite，并为地图 API 和模型 API 留出替换点。

Browser

Order console

HTTP 3000 托管前端；REST 创建订单和边权；WebSocket 接收状态、图像、语音事件。

Backend

UDP gateway

8898 下发订单和控制，8888 接收 JPEG 图传，8899 处理语音模型命令。

Vehicle

Navigation core

订单调度、动态 Dijkstra、AprilTag 定位、屏幕提示、语音播报和运动控制。

SQLite

Trace store

订单、边权、语音命令、小车状态快照全部持久化。

Persistent Operations

Every decision leaves a trace.

调度结果、路况权重、语音命令和车辆状态都进入电脑端 SQLite。演示结束后仍能复盘：谁下了单、哪条边变贵、语音命令如何解析、小车当时在哪里。

SQLite tables

ordersmission state and car response
edge_conditionsmanual weight, dynamic weight, blocked
voice_command_logstext, action, source, request, result
car_status_snapshotsnavigation and scheduler state
