订单控制通道

语音模型网关

Two campus maps

节点 ID 与屏幕目标、AprilTag、Dijkstra 节点统一，减少地图和硬件之间的映射误差。

Order lifecycle

订单不是单次导航，而是一组带有取放约束的站点动作。

创建订单

电脑端选择地图、起点和终点。

到达起点

屏幕和语音提示“请放入物品”。

运输与重规划

根据人工权重、拥堵、天气或封路更新路径成本。

到达终点

提示“请取走物品”，确认后订单完成并持久化。

Communication protocol

电脑端负责 HTTP/WebSocket/UDP 网关，小车端只处理轻量 JSON 和本地硬件控制。

Message stream

HTTP 3000 create order
UDP 8898 submit_order
WebSocket status_response

Persistent data

电脑端 SQLite 记录系统可追踪状态，重启后仍可查询订单、边权、语音和小车状态。

TablePurpose
orders订单 ID、地图、起点、终点、状态、最后响应
edge_conditions人工权重、动态权重、封路配置
voice_command_logs语音文本、解析动作、规则/模型来源
car_status_snapshots小车实时状态快照
